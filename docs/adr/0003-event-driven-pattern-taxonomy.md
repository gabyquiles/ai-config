# Event-driven patterns are grouped into Event Styles / Messaging & Integration / Coordination & Delivery

The `event-driven/` pattern family (added per [0002](0002-pattern-family-subfolders.md)) needed a category grouping for `SKILL.md`'s index, the way GoF patterns are grouped into Creational/Structural/Behavioral. Unlike GoF, there's no canonical taxonomy to reflect — the reference source used to compile this family (eda-visuals.boyney.io) is a loose catalog with no formal categories of its own. We grouped the 14 patterns into three categories by what they're about: Event Styles (how state changes are represented and propagated — Event Notification, Event-Carried State Transfer, Event Sourcing, CQRS, Change Data Capture), Messaging & Integration (transforming, enriching, and routing messages — Content-Based Router, Message Translator, Content Enricher, Claim Check, Splitter), and Coordination & Delivery (reliable processing and multi-step coordination — Competing Consumers, Idempotent Consumer, Choreography Saga, Orchestration Saga). This mirrors GoF's 3-category precedent for scannability, while keeping each category's membership defensible on its own terms rather than forced to match GoF's specific boundaries.

## Considered Options
- **No categories, flat list of 14** — rejected: harder to scan than GoF's precedent, and loses the grouping signal that helps a reader jump to the right pattern for their situation.
- **Mirror the source site's loose thematic clusters** (messaging infrastructure, communication styles, architectural concepts, infrastructure & delivery, design & governance, system challenges, strategic topics — roughly 7 groups) — rejected: too many groups for 14 patterns, inconsistent boundaries, and several of the site's clusters (governance, strategy, Conway's Law) aren't patterns at all and fall outside this skill's scope entirely.
