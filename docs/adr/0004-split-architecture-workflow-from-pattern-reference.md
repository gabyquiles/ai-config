# Architecture design and documentation gets its own skill, separate from the renamed pattern-reference skill

`software-architecture` was a passive, index-only reference for GoF and event-driven patterns — it had no way to actually drive the design of a new system or scaffold documentation for one. Rather than growing that skill a second, incompatible mode (interview → diagram → scaffold), we split it: `design-patterns` (the rename) stays a pure lookup index, unchanged in content; `software-architect` is a new, active workflow skill for designing and documenting architecture using arc42 (doc structure), C4 (high-level diagrams, Mermaid), and a curated core of UML diagrams (Class, Sequence, State Machine, Component) for detail C4 doesn't capture. Each new family's internal shape is sized to how it's actually used rather than forced into `design-patterns`' flat-pattern-file template (established in [0002](0002-pattern-family-subfolders.md)): `arc42.md` is one file at the skill root, since its 12 sections are a single template always used together; `c4/` holds one file per zoom level (three), since the levels are produced together as a progressive set but stay independently loadable; `uml/` holds one file per diagram type (four), matching `design-patterns`' existing one-file-per-selectable-item model, since UML diagram types are genuinely chosen independently per situation. The new skill's name initially overlapped closely with the `solutions-architect` agent (AWS/cloud trade-off persona); rather than renaming `software-architect`, that agent was instead renamed to `aws-solutioner` to make its AWS-only scope unmistakable, and both files cross-reference the other's distinct job so the overlap resolves by handoff instead of confusion.

## Considered Options
- **One skill covering both pattern-lookup and active design** — rejected: an index-only reference and an interview-driven, file-scaffolding workflow are different enough jobs (different triggers, different `<what-to-do>` shape) that folding them together would have made a single `SKILL.md` do two unrelated things.
- **Force arc42/C4/UML into `design-patterns`' flat per-pattern-file template uniformly** — rejected: arc42's 12 sections and C4's zoom levels aren't independently selectable patterns the way GoF/EDA patterns are; flattening them would misrepresent what they are.
- **Put arc42 content in a subfolder (`arc42/sections.md`) for symmetry with `c4/` and `uml/`** — rejected: a subfolder holding exactly one file adds nesting with no payoff; `arc42.md` lives flat at the skill root instead.
- **Resolve the naming collision with a cross-reference only, keeping both names as-is** — superseded: initially chosen, but revisited in favor of renaming `solutions-architect` to `aws-solutioner`, since the collision (and the agent's actual AWS-only scope) was clearer to fix at the source than to paper over with a note in each file.
